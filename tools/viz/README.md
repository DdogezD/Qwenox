# 运行时视图

`qwenox-viz.html` 在浏览器里实时显示模型正在做什么：每个 token 在 48 层里各选了哪 10 个专家（512 个专家的版图），每层路由有多犹豫，下一个 token 的前 5 个候选，以及 MTP 每轮 verify 收下了几个 token。

## 使用

1. 在 `service.conf` 里设 `VIZ=1`，重启服务。启动日志里会有一行 `viz: taps on`。
2. 在任意一台能访问这台机器的电脑上，用浏览器直接打开 `tools/viz/qwenox-viz.html`（本地文件即可，不需要服务器）。
3. 页面右上角填 API 地址，例如 `192.168.5.12:8731`。
4. 用平常的客户端发消息。页面默认跟随最新的请求；并发时可以在"会话"里固定看某一路。

页面上的操作：

- 点 token 流里的某个 token，版图和右侧仪表就停在那个 token 的路由上；点"跟随最新 token"回到实时。
- "累计"把版图切成本次请求里每个专家承担了多少路由，用来看哪些专家是热点。
- 鼠标停在版图上，显示层号、专家号、本次请求里它承担的份额和它在当前 token 的权重。

## 代价与范围

- `VIZ=0`（默认）时引擎不分配、不写任何东西。
- `VIZ=1` 时 decode 约慢 1%，另外按并发路数各占约 6 MiB 锁页主机内存。
- 每路保留最近 2048 个位置的路由。更早的位置只显示文字，不显示路由。
- 记录的是主干 48 层。MTP 草稿层不记录，草稿被拒的行也不会显示出来。
- prompt 的最后一个位置没有候选，因为它的 logits 走 prefill 路径，不经过记录点。
- 来自 SSD/内存检查点恢复的 prompt 部分没有路由，因为这一轮没有重新计算它们。
- 开启后，局域网里能访问 API 端口的人都能通过 `/viz` 看到正在生成的内容。

## 数据接口

`GET /viz` 返回各路概况；`GET /viz?slot=S&from=F&n=N` 返回该路 `[F, F+N)` 位置的记录（N ≤ 256）。字段含义写在 `src/gpu/parts/19_viz.inc` 的注释里。主要字段：

| 字段 | 含义 |
|---|---|
| `t` / `b` | token id / 它的原始字节（hex） |
| `m` | 生成 token 发出的时刻（距请求开始的毫秒数），prompt 为 -1 |
| `e` / `w` | 48×10 个专家 id / 权重（×255），按层排列 |
| `c` / `h` | 每层选中 10 个专家的概率质量 / 路由熵（均 ×1000） |
| `k` / `q` / `kb` | 下一个 token 的前 5 候选 id / 概率（×10000）/ 字节 |

## 验证

`bash tools/viz_verify_win.sh [不带埋点的引擎.exe]` 依次启动各配置，检查输出逐 token 一致、数据与位置对齐，最后打印 PASS/FAIL；加 `SPEED_ROUNDS=2` 做测速 A/B。运行前需要先停掉生产服务。
